# Durable jobs

Redis is the existing authoritative database. Hashes store jobs/reports/checkpoints, an owner sorted set indexes history, an active sorted set provides dispatch, session locks serialize conversation turns, and streams persist progress. Use a persistence-enabled Redis primary; this implementation does not support Redis Cluster multi-slot Lua operations.

Admission is one Lua transaction: owner-scoped idempotency lookup/fingerprint, capacity checks, durable job, history index, queue publication and event. There is no separate publication window requiring a SQL outbox. Limits: ten new submissions per principal/minute, five active jobs per principal by default, 1,000 active jobs globally. Same key/different scope, question, session or model conflicts.

States: `QUEUED → RUNNING → SUCCEEDED | FAILED | TIMED_OUT`; queued cancellation is immediately `CANCELLED`, running cancellation uses `CANCEL_REQUESTED → CANCELLED`. Reclaim can advance `RUNNING` to a new generation. Three claims maximum; expired original deadlines and exhausted attempts terminate during queue reconciliation. Partial analysis is a report classification (`PARTIAL`), not a fabricated execution success percentage.

Worker claim, heartbeat, progress, checkpoint and finish use owner/generation/lease comparisons. Cancellation wins a concurrent finish. Final report, terminal event and conversation turn commit atomically; stale owners receive `LOST`. A Redis outage cancels active reasoning when heartbeats fail. Polling and worker-readiness pulses recover after transient Redis errors. Shutdown gives work five seconds, then interrupts it and leaves the lease reclaimable.

User retry accepts only `FAILED` or `TIMED_OUT`. It creates a new job linked to its parent using the current server model and a fresh deadline. The failed job remains immutable apart from its successor link. Authorization, eligibility, admission and the single-successor link are one Lua transaction. Replaying the same retry key returns the child; a different key conflicts. Retry the failed child to create a subsequent attempt. Retry may incur provider charges again.

Retention defaults to 86,400 seconds after terminal completion; configure `RESEARCH_RETENTION_SECONDS` (1 hour–1 year). Jobs already terminal keep their existing TTL when policy changes. New fields are additive and old jobs without scope/metadata remain readable/retryable. The existing `scripts/migrate_execution_index.py` reconstructs old owner indexes without deleting records; run dry-run first. History uses an ID cursor to handle equal timestamps and lazily removes expired index entries. Back up Redis before migration or rollout. A rollback must not remove completed history or enable an unfenced old worker against new active jobs; drain workers first.
